════════════════════════════════════════════════════════════════════════════
API CONTRACT (base: same-origin `/api`)
════════════════════════════════════════════════════════════════════════════

All responses are JSON. Error responses carry a `message` field (Persian).
Handle at minimum: `401` (redirect to login), `403` (forbidden), `404`
(not found), `409` (conflict — duplicate review / re-moderation).

Common shapes:

Review (customer-facing, used by list/detail/mine/summary endpoints):
  {
    id: string,              // UUID
    rating: number,          // 1..5
    title: string | null,    // optional, max 100 chars
    text: string,            // review body, 10..1000 chars
    status: "PENDING" | "APPROVED" | "REJECTED",
    rejectReason: string | null,
    moderatedAt: string | null,   // ISO date
    createdAt: string,
    updatedAt: string,
    name: string              // reviewer display name
  }

Paginated list response:
  {
    items: Review[],
    meta: { total: number, page: number, limit: number,
            totalPages: number, hasNext: boolean, hasPrev: boolean }
  }

Summary (from list response or the summary endpoint):
  {
    average: number,                 // e.g. 4.5
    count: number,
    distribution: [n5, n4, n3, n2, n1]  // count per rating, index 0 = 5 stars
  }

────────────────────────────────────────────────────────────────────────
CUSTOMER ENDPOINTS (`/api/site-reviews`)
────────────────────────────────────────────────────────────────────────

POST /site-reviews
  Auth: required (logged-in user). Rate-limited server-side (5/min).
  Body: { rating: number (1..5), title?: string (<=100),
          text: string (10..1000) }
  201 → full review object (includes `userId`, `user: { id, name }`).
  409 → user already has a review ("شما قبلاً نظر خود را ثبت کرده‌اید...").

GET /site-reviews
  Public (guest OK; optional auth). Returns APPROVED reviews only.
  Query: page (default 1), limit (default 10, max 50),
         rating (1..5 filter), sort = "newest" | "highest" | "lowest"
         (default "newest"), q (search text/reviewer name)
  200 → { items, meta, summary } (summary over ALL approved reviews).

GET /site-reviews/summary
  Public. 200 → { average, count, distribution }.

GET /site-reviews/mine
  Auth required. 200 → { items: Review[] (all statuses, newest first),
  meta }.

GET /site-reviews/:id
  Public with optional auth. 200 → Review. 404 when: not found, or the
  review is not APPROVED and the caller is not the owner.

PATCH /site-reviews/:id
  Auth required. Owner only (403 otherwise).
  Body: { rating, title?, text } (same constraints as create).
  200 → updated review. Status is reset to PENDING (resubmitted for
  moderation) and any previous rejectReason is cleared.

DELETE /site-reviews/:id
  Auth required. Owner only (403 otherwise). 200 → { message }.

────────────────────────────────────────────────────────────────────────
ADMIN ENDPOINTS (`/api/admin/site-reviews`)
────────────────────────────────────────────────────────────────────────

Admin review shape = customer review shape + { userId, moderatedBy }.

GET /admin/site-reviews
  Admin auth + RBAC (site-review:view). All statuses.
  Query: page (default 1), limit (default 20, max 50),
         status = "PENDING" | "APPROVED" | "REJECTED",
         rating (1..5), q (search text/title/reviewer name),
         userId (UUID filter)
  Ordering: PENDING first, then by rating desc, then newest.
  200 → { items, meta }.

GET /admin/site-reviews/:id
  Admin auth + RBAC (site-review:view). 200 → admin review object.

PATCH /admin/site-reviews/:id/approve
  Admin auth + RBAC (site-review:moderate).
  200 → admin review object, status now "APPROVED".
  409 → already moderated (one-way moderation).

PATCH /admin/site-reviews/:id/reject
  Admin auth + RBAC (site-review:moderate).
  Body: { reason?: string (<=255) }
  200 → admin review object, status now "REJECTED".
  409 → already moderated.

DELETE /admin/site-reviews/:id
  Admin auth + RBAC (site-review:delete). Hard delete (spam removal).
  200 → deleted review object.
